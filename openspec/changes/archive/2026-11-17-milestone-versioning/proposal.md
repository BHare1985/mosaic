# Proposal

## Why

The project reports `0.1.0`, which is the number the C++ template shipped with. Since then it has gained ten modules, nineteen
capability specs, a transport on a real network, durability, resilience, jobs and a daemon - and the version has not moved once. So
`Mosaic version` tells a reader nothing true, and there is no rule that would tell them what the next number should be.

The version is also only expressible as preprocessor macros (`MOSAIC_VERSION`, `MOSAIC_VERSION_MAJOR`, ...) generated by
PackageProject, which is the C++98 way to carry a constant into C++20 code.

## What Changes

- **A rule for the number:** `0.<milestones closed>.0`. Six milestones are closed (M0 scaffold through M5 jobs), M6 reach is in
  progress, so the version is **0.6.0**. Closing M6 makes 0.7.0. The patch component is reserved for fixes and never carries
  features.
- CMake's `project(... VERSION ...)` stays the single source of truth; everything else derives from it.
- The generated version header becomes idiomatic C++20: `inline constexpr std::string_view kVersion`, `kVersionMajor/Minor/Patch`
  as `std::uint32_t`, a `kMilestonesClosed` constant that states why the minor number is what it is, and a `static_assert` tying the
  components to the string. The `MOSAIC_VERSION` macro survives as a thin alias, because CMake and PackageProject reference it.
- A `CHANGELOG.md` with the 0.6.0 entry, written from the archived changes' summaries rather than from memory.
- Each document in `docs/design/` states the version it describes in one line, so a reader knows whether the prose is current.
- The CLI prints `mosaic::kVersion`, the site shows it, and a test asserts the header agrees with CMake's version so the two cannot
  drift.
- **Not** in scope: declaring 1.0.0 (the API is not stable until the C ABI lands), git tags or releases, or a compatibility policy
  beyond "0.x may break between minors".

## Capabilities

None: a version string and how it is generated is tooling. The change declares `skip_specs: true`.

## Impact

- `CMakeLists.txt` (`project(... VERSION 0.6.0)`), `cmake/version.h.in` (new, replacing PackageProject's macro header), the CLI's
  `version` command, `CHANGELOG.md` (new), every `docs/design/*.md` header line, `docs/site/pages/about.dox`.
- A test that compares the compile-time version against the CMake project version, so a bump in one place and not the other fails
  the build.
- `docs/design/conventions.md`: the numbering rule, stated once.
